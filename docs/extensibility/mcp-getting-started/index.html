Model Context Protocol - Getting Started

Overview​

The SailPoint MCP (Model Context Protocol) Server enables AI applications to interact with SailPoint's identity governance platform through a standardized interface. This guide shows you how to connect to the SailPoint MCP servers with the MCP Inspector and test the available tools.

What you'll accomplish:

  • Create an API client in SailPoint Identity Security
  • Prepare the SailPoint config file
  • Launch the MCP Inspector with the SailPoint servers
  • Connect and authenticate with your SailPoint tenant
  • List and explore available tools

Servers​

SailPoint provides more than one MCP server. Each server has its own URL, its own scope, and its own set of tools:

ServerGlobal URLScopePurpose
Access Requestshttps://mcp.sailpoint.com/latest/access-requests/mcpidn:access-request:manageSearch for requestable items, and create, view, and cancel access requests.
Identity Intelligencehttps://mcp.sailpoint.com/latest/intelligence/mcpsp:identity-sec-intel:readInvestigate human identities: profile, access, risk, access history, and certifications. Read-only.

The global URLs work for all tenants without any tenant-specific configuration. They are the recommended entry point for AI client integration.

Prerequisites​

Before you begin, make sure that you have:

  • Access to a SailPoint tenant with API access enabled, and permission to create API clients
  • Node.js installed, so that you can run npx
  • Modern web browser (Chrome, Firefox, Safari, or Edge)

Step 1: Create an API Client in SailPoint Identity Security​

AI clients use OAuth to sign you in to your tenant. SailPoint's authorization server does not support Dynamic Client Registration, so you must create an API client in SailPoint Identity Security and give its Client ID to your AI client.

In SailPoint Identity Security, go to Admin > Security Settings > API Management and create a new API client:

  1. Set the client type to Public.
  2. Enable the Authorization Code and Refresh Token grant types.
  3. Set the Redirect URL to the OAuth callback URL of your AI client, as listed in the table below.
  4. Set the Scope to the scope of each server that you want to use, as listed in Servers. If you use both servers with one Client ID, add both scopes.

Save the client and copy the Client ID.

Use the redirect URL of your AI client from this table. To use one Client ID with the MCP Inspector and other AI clients, add both redirect URLs.

AI clientRedirect URL
MCP Inspectorhttp://localhost:6274/oauth/callback
Claude Code, Claude Desktop, Cursor, VS Codehttp://localhost:13509/oauth/callback

The AI clients in the second row connect through mcp-remote. The port 13509 in the redirect URL must match the port in the args of the MCP configuration of the client.

Step 2: Prepare the SailPoint Config File​

  1. Download the ready-made Inspector config: sailpoint-mcp-inspector.json. It contains:

    {
      "mcpServers": {
        "sailpoint-access-requests": {
          "type": "streamable-http",
          "url": "https://mcp.sailpoint.com/latest/access-requests/mcp",
          "oauth": {
            "clientId": "YOUR_CLIENT_ID",
            "scopes": "idn:access-request:manage"
          }
        },
        "sailpoint-identity-intelligence": {
          "type": "streamable-http",
          "url": "https://mcp.sailpoint.com/latest/intelligence/mcp",
          "oauth": {
            "clientId": "YOUR_CLIENT_ID",
            "scopes": "sp:identity-sec-intel:read"
          }
        }
      }
    }

  2. Open the file and replace each YOUR_CLIENT_ID with the Client ID from Step 1. You can use the same Client ID for every server.

The oauth block fills in the OAuth settings for each server, so you do not need to enter them in the Inspector:

  • clientId: the Client ID of your SailPoint Identity Security API client.
  • scopes: the OAuth scopes to request for that server. The file already contains the scope of each server, as listed in Servers. Enter scopes as one string, separated by spaces, not as an array. If a field has the wrong type, the Inspector ignores the whole oauth block.

Do not add a clientSecret. The SailPoint Identity Security API client is a public client that uses PKCE.

Only need one server?

Delete the servers you don't need from sailpoint-mcp-inspector.json.

Step 3: Launch the MCP Inspector​

The MCP Inspector is a web-based tool that you can use to connect to and test MCP servers without writing code.

In the folder that contains sailpoint-mcp-inspector.json, run this command:

npx @modelcontextprotocol/inspector@latest --catalog sailpoint-mcp-inspector.json

If this is your first time running the command, npm asks to install the package. Enter y to confirm. Your default web browser then opens the MCP Inspector.

The Inspector opens on the Servers page. The page shows a card for each server in the file: sailpoint-access-requests and sailpoint-identity-intelligence. Each card shows the transport (Streamable HTTP), the server URL, and these actions:

  • Clone, Edit, and Remove: copy, change, or delete the server.
  • Settings: change the OAuth settings, headers, and other connection options.
  • Connection Info: show details about the connection. This action shows only while the server is connected.

The --catalog flag lets the Inspector save the changes you make in the UI back to the file. To load the file without changing it, use --config instead of --catalog.

Import the file into a running Inspector

If the Inspector is already open, you can import the file instead. Select Add Servers ▾ in the top-right corner of the Servers page, then choose client config, and select sailpoint-mcp-inspector.json.

Step 4: Connect to a Server​

  1. On a SailPoint server card, select the toggle next to Disconnected.
  2. When you connect to a server for the first time, the Inspector opens a browser window. Log in with your SailPoint Identity Security credentials and approve the consent screen. If the tenant cannot be determined from your Client ID, you are prompted to enter your tenant name.

When the connection succeeds:

  • The server card has a green border, and its status changes from Disconnected to Connected.
  • The card shows the MCP protocol version of the server, for example MCP 2025-11-25.
  • The top bar shows the name of the server and Connected, with the connection time.
  • The Messages panel on the right shows the initialize, notifications/initialized, and tools/list messages, each marked OK.

While one server is connected, the other server cards are dimmed. To use another server, turn off the toggle on the connected card, then turn on the toggle on the other card.

Tokens refresh automatically after you sign in.

Step 5: List Available Tools​

  1. Connect to a server, as described in Step 4.
  2. Select Tools at the top of the page.

The Tools page shows the tools of the connected server, with their descriptions and parameters. Each server returns only its own tools. To see the tools of the other server, connect to that server and open Tools again.

The Access Requests server provides four tools, and the Identity Intelligence server provides two. For details, refer to Available Tools.

Manual Setup​

Use these steps only if you cannot use the config file from Step 2.

Add a server manually

  1. Launch the Inspector without a config file:

    npx @modelcontextprotocol/inspector@latest

  2. On the Servers page, select Add Servers ▾ in the top-right corner, then choose Add manually.

  3. Set the Transport Type to Streamable HTTP.

  4. Enter the global URL of the server, as listed in Servers.

  5. Save the server.

  6. On the server card, select Settings and expand OAuth Settings. Then set:

    • Client ID: the Client ID from Step 1
    • Client Secret: leave blank (the SailPoint Identity Security client is a public client that uses PKCE)
    • Scopes: the scope of the server, as listed in Servers (space-separated, no commas)

  7. Leave Enterprise-managed authorization unchecked.

  8. To add another server, repeat steps 2 to 7 with that server's URL.

Then continue to Step 4.

The Inspector finds SailPoint's authorization and token endpoints from the server's .well-known metadata. If you must enter the endpoints by hand, use these URLs:

EndpointURL
Authorizationhttps://login.sailpoint.com/oauth/authorize
Tokenhttps://api.identitynow.com/oauth/token
Use the tenant-specific URL with a bearer token

Customers with FedRAMP or data sovereignty requirements must use the tenant-specific URL instead of the global URL:

ServerTenant-specific URL
Access Requestshttps://[tenant].api.identitynow.com/latest/access-requests/mcp
Identity Intelligencehttps://[tenant].api.identitynow.com/latest/intelligence/mcp

Replace [tenant] with your tenant name. For example, if your SailPoint URL is https://acme.identitynow.com, the Access Requests URL is https://acme.api.identitynow.com/latest/access-requests/mcp.

With the tenant-specific URL, you authenticate with a bearer token:

  1. Generate an access token. For instructions, refer to the Authentication documentation.

  2. Make sure that the token has the necessary permissions for the tools that you want to use.

  3. In sailpoint-mcp-inspector.json, change each URL to the tenant-specific URL. Replace each oauth block with a headers block that contains your token:

    {
      "mcpServers": {
        "sailpoint-access-requests": {
          "type": "streamable-http",
          "url": "https://[tenant].api.identitynow.com/latest/access-requests/mcp",
          "headers": {
            "Authorization": "Bearer YOUR_ACCESS_TOKEN"
          }
        },
        "sailpoint-identity-intelligence": {
          "type": "streamable-http",
          "url": "https://[tenant].api.identitynow.com/latest/intelligence/mcp",
          "headers": {
            "Authorization": "Bearer YOUR_ACCESS_TOKEN"
          }
        }
      }
    }

  4. Launch the Inspector with the file, as described in Step 3.

If you added the servers manually, select Settings on each server card instead, and add an Authorization header with the value Bearer YOUR_ACCESS_TOKEN.

Next Steps​

Now that you have a working connection, you can:

  • Explore available tools - Learn about each tool's capabilities in our Available Tools guide
  • Test tool execution - Try running tools with different parameters to understand their behavior
  • Build integrations - Use the MCP protocol in your AI applications to automate SailPoint operations
